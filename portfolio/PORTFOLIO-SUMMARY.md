# Vercel Build Troubleshooting Demo

## Problem

A Next.js application compiled successfully locally but failed the real Vercel CLI local build pipeline.

## Diagnosis

Comparing the output generated by Next.js with the deployment configuration isolated the failure to the declared output directory.

## Root Cause

`vercel.json` expected `dist`, while the application generated Next.js's default `.next` directory. Local compilation did not validate this Vercel-specific setting.

## Fix

Remove only the erroneous `outputDirectory` setting from `vercel.json`, restoring framework-default detection. Fixed commit: `3f0a5a5`. Its tracked contents match the validated baseline exactly.

## Validation

Baseline: nine unit/integration tests, five production-browser scenarios, typecheck, lint, Next.js build, and real Vercel CLI local build passed.

Broken: Next.js build passed with exit 0; Vercel build failed with exit 1 and reported that the configured `dist` directory was missing.

Fixed: nine unit/integration tests, five production-browser scenarios, typecheck, lint, Next.js build, and the real Vercel CLI local build all passed. Generated build output was cleaned before Vercel validation. The deployment verifier’s SHA-256 digest is identical across baseline, broken, and fixed.

A separate machine reproduced baseline and broken behavior, and independent diagnosis converged. Independent final audit approved the fix; it was merged after approval.

Cloud preview was not used because no safe free scope was available. Zero production dependency advisories; 27 development-toolchain advisories remain documented.
